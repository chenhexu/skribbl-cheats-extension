# Blueprint treatment 2.2.5

Validated October 25, 2026. The screenshot showed light blueprint ink being converted into filled gray regions with added black contours. The new light-lines treatment separates a dominant dark background from bright source ink, suppresses weak grid contrast, thins ink to centerlines, and draws white paths over a required background layer. It reuses the shared plan, spline fitting, preview, bucket verification, and CDP executor.

Auto requires sparse bright strokes, a predominantly dark field, and low foreground interior coverage. A broad white object on a dark background does not trigger it. The manual treatment selector remains available. Color count, shade merging and near-white removal do not apply to this two-color treatment; the remaining controls work normally. Background fills are prerequisites, so runtime outline reserves cannot skip them. The line budget uses the time left after the background rather than reserving two thirds for extra color regions.

Added checks for Auto recognition versus broad white shapes, transparent letterboxing, faint-grid rejection, single white loops, nearby disconnected strokes, no gray/black overdraw, one required background, deterministic plans despite saved latency, AI mask alignment/errors, cancellation, and remaining-budget allocation.

New treatment: 223 drags, one bucket click, 353 moves, 800 events, two colors, and a 6.91-second estimate. That is about 65% fewer drags and 79% fewer events; these estimates do not establish a live-room speed guarantee.
- The complete new plan was executed with trusted Chrome CDP pointer events in the local game fixture in about 10 seconds. It selected Fill for the background and restored Brush for white paths. Blue background and white ink pixels were checked, the required background was not skipped, and the debugger detached afterward. No live room was joined.
- A real CPU Informative Drawings checkpoint comparison retained white source ink with no added gray or black stages: 217 drags, one bucket, 337 moves, 772 events. The model filters supported bright-ink components rather than outlining both sides of each stroke. It dropped some small window details, so Browser remains useful for faithfully tracing bright source ink.
- Both final previews, the executed canvas, and the compact panel were visually inspected. The new selector initially overflowed the narrow panel; field sizing now fits the 320-pixel layout. Treatment and manual edits round-trip between compact and expanded viewers. All existing guesser, drawing, Auto, cancellation, service failure, and execution regression checks remain in the suite.

Weak grids and short dashes can disappear along with noise. Increase Outline detail to retain more. Equally bright grid and subject lines cannot always be distinguished by this contrast-based treatment. Stroke widths are limited by the game's minimum 4-pixel brush. This release does not perform semantic object, text, or grid removal, retrain the model, or publish to the store.

Run `npm test`, `npm run test:ui`, then `npm run package`. Reload the unpacked extension and refresh Skribbl, or hard-refresh the local viewer, and reprocess the image. The Python service itself does not need a restart for these JavaScript changes.
